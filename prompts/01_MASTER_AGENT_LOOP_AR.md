# برومبت مستمر — حلقة عمل الوكيل حتى اكتمال المشروع

التزم بهذه التعليمات في كل مرحلة من مراحل المشروع، ولا تعتبرها مهمة لمرة واحدة.

## دورة العمل الإلزامية
1. اقرأ `README_AR.md` و`docs/IMPLEMENTATION_PLAN.md` و`PROJECT_STATUS.md` وملفات البيئة النموذجية والاختبارات ذات الصلة.
2. افحص الكود الحالي فعليًا؛ لا تفترض أن ما وصفه تقرير سابق ما زال صحيحًا.
3. حدّد المرحلة الحالية ومعايير قبولها، وما هو مكتمل وما هو غير مكتمل.
4. اكتب خطة قصيرة للتغييرات التالية والملفات التي ستتأثر.
5. نفّذ جزءًا صغيرًا قابلًا للاختبار. لا تعِد كتابة أجزاء سليمة بلا سبب.
6. شغّل format/lint/typecheck/tests/build ذات الصلة.
7. أصلح الإخفاقات الناتجة عن تغييراتك قبل الانتقال.
8. حدّث التوثيق و`PROJECT_STATUS.md` بالحقائق والأوامر والنتائج.
9. إذا كان هناك نقص في credentials، نفّذ كل ما يمكن اختباره دونها، ثم اكتب اسم المتغير الناقص فقط، لا تطبع قيمته.
10. توقّف فقط عند اكتمال معايير المرحلة أو وجود عائق لا يمكن تجاوزه بأمان.

## الاستئناف بعد التوقف
- عند بداية كل جلسة، اقرأ `PROJECT_STATUS.md` وسجل Git والاختبارات.
- لا تبدأ من الصفر مرة أخرى ولا تعِد تنفيذ تغييرات موجودة.
- افحص آخر commit و`git diff` قبل أي تعديل.
- استأنف من أول معيار قبول غير مكتمل.
- لا تعلن اكتمال ميزة اعتمادًا على وجود ملف فقط؛ اختبر مسارها من الواجهة إلى قاعدة البيانات والخدمة المطلوبة.

## سياسة الصدق
استخدم حالات: `NOT STARTED`, `IN PROGRESS`, `BLOCKED`, `PASS`, `FAIL`.
لا تستخدم `PASS` إلا مع اختبار حقيقي. افصل بين:
- implemented
- locally tested
- integration tested
- production verified

## الأمان
- لا تطبع secrets أو JWTs أو بيانات شخصية في logs أو التقارير.
- لا تضع مفاتيح سرية في prompts أو source control.
- لا تضع أي server secret في متغير `NEXT_PUBLIC_*`.
- لا تثق في role أو subject_id من العميل دون authorization server-side.
- افحص التبعيات والـ CORS ورفع الملفات والتحقق من JWT.
- لا تُنفذ migrations مدمرة أو حذف بيانات دون موافقة.

## عند وجود خطأ
- احصل على stack trace أو رسالة خطأ آمنة كاملة.
- حدد السبب الجذري قبل تغيير عدة ملفات.
- أنشئ regression test عند الإمكان.
- لا تخفِ الخطأ برسالة نجاح وهمية أو fallback صامت.
- لا تبدّل provider أو model أو schema تلقائيًا دون توثيق السبب.

## Definition of Done لكل مرحلة
- تنفيذ معايير القبول.
- اختبارات ذات صلة ناجحة.
- تحديث docs وPROJECT_STATUS.
- توضيح ما بقي وما يتطلب إدخال المستخدم.
